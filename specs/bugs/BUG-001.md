# BUG-001: `/scoped-models` is print-only

## Problem

`/scoped-models` currently prints the discovered models as a plain list. It does not open a selectable vertical model list, does not support selecting/toggling models through the UI, and does not save the resulting scope for later `/model` and Ctrl+P use.

Expected behavior, matching Pi: `/scoped-models` opens an interactive model-scope selector, allows the user to change enabled models and their order, and saves the selection. `/model` then selects from the saved scope.

Minimal reproduction:

1. Start Mia with at least one connected provider.
2. Run `/scoped-models`.
3. Observe a text printout such as `Scoped models: ...` and no selection UI.
4. Restart or run `/model`; no saved scope is available from the command interaction.

Baseline evidence: Ruff, strict Mypy, plan consistency, and 101 tests pass before the fix.

Security impact: NONE. No security exploit path identified; this is a local interactive UX/state defect.

## Root Cause Analysis

### Phase 1 — Reproduce

Environment: Mia worktree `bug-001-scoped-model-selector`, Python 3.14, MockProvider, one stored OpenAI test credential.

Command: `uv run --offline python` minimal reproduction with `MiaREPL.handle_slash_command("/scoped-models")`, patched provider discovery, and a public `interactive_select` spy.

Observed output:

```text
Scoped models:
  openai: gpt-4o
```

The reproduction passed only because it demonstrated the defect: the output was printed and `interactive_select` was never called (`select.called == False`).

### Phase 2 — Isolate

Recent history shows the model-picker work was split across `a37b903` and `42a9b0b`. The defect is isolated to the `/scoped-models` branch of the public slash-command handler. It calls discovery, mutates in-memory scope state, and prints labels; it has no selector invocation, multi-selection state transition, or persistence call. `/model` and Ctrl+P consume `scoped_models`, so they cannot provide the missing save transition themselves.

### Phase 3 — Hypotheses

1. **Confirmed candidate:** the command is implemented as a print/status branch rather than an interactive selection branch.
2. Provider discovery is broken. **Falsification:** the minimal reproduction returns `openai: gpt-4o`; discovery produces usable model IDs.
3. The generic selector cannot render a vertical list. **Falsification:** `interactive_select` already renders numbered vertical options for login and model selection. The missing piece is scope-specific multi-selection/save behavior, not rendering capability.
4. Config persistence is the only missing behavior. **Falsification:** even before persistence, the command must open a selector; the reproduction proves the first failure is the absent interaction boundary.

### Phase 4 — Verified root cause

The command's observable implementation ends after printing the list. No selector invocation or scope-save operation exists on that path. The minimal reproduction, source isolation, and hypothesis falsification confirm one root cause: `/scoped-models` lacks an interactive selection-and-save workflow.

Risk: Medium. The fix changes a shared CLI interaction path and scope persistence, but remains local to model selection and has no remote/security boundary.
