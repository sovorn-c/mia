# BUG-001: `/scoped-models` is print-only

## Problem

`/scoped-models` currently prints the discovered models as a plain list. It does not open a selectable vertical model list, does not support selecting/toggling models through the UI, and does not save the resulting scope for later `/model` and Ctrl+P use.

Expected behavior, matching Pi: `/scoped-models` opens an interactive model-scope selector, allows the user to change enabled models and their order, and saves the selection. `/model` then selects from the saved scope.

Minimal reproduction:

1. Start Mia with at least one connected provider.
2. Run `/scoped-models`.
3. Observe a text printout such as `Scoped models: ...` and no selection UI.
4. Restart or run `/model`; no saved scope is available from the command interaction.

Baseline evidence: Ruff, strict Mypy, plan consistency, and 101 tests pass before the fix.

Security impact: NONE. No security exploit path identified; this is a local interactive UX/state defect.

## Root Cause Analysis

### Phase 1 — Reproduce

The public slash-command handler invokes model discovery and then prints the current scope. It does not call the existing interactive selector and does not persist scope state. The current test suite covers discovery and in-memory lists but has no public-behavior test for interactive scope selection or persistence.

### Phase 2 — Isolate

The defect is isolated to the `/scoped-models` command path and the absence of a persistence boundary for scoped-model settings. `/model` already consumes `scoped_models`, while `Ctrl+P` already cycles that list; the missing operation is the user-facing selector/save transition.

### Phase 3 — Hypotheses

1. **Confirmed candidate:** the command is implemented as a print/status branch rather than an interactive selection branch.
2. Provider discovery is broken. **Falsification:** discovery returns model IDs and `/model` can consume them; discovery is not the cause of the print-only behavior.
3. The generic selector cannot render a vertical list. **Falsification:** `interactive_select` already renders numbered vertical options for login/model selection; it is reusable, though scope selection needs multi-selection/save behavior.

### Phase 4 — Verified root cause

The command's observable implementation ends after printing the list. No selector invocation or scope-save operation exists on that path. The minimal reproduction and source isolation confirm the single root cause: `/scoped-models` lacks an interactive selection-and-save workflow.

Risk: Medium. The fix changes a shared CLI interaction path and scope persistence, but remains local to model selection and has no remote/security boundary.
